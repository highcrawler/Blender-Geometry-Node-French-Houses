# Phase 9F – implementation of the rectangular wooden roof

**Blender 5.2.2 LTS.** Public package: [`roof/__init__.py`](../roof/__init__.py) re-exports [`RoofSpec`, `RoofResult`, `build_rectangular_roof`](../roof/wooden_rect.py). Import from a Blender script with the repository root on `sys.path`:

```python
from roof.wooden_rect import RoofSpec, build_rectangular_roof
spec = RoofSpec(width_m=5.1, depth_m=7.3, wall_height_m=2.3,
                pitch_degrees=40, seed=23, appearance='CLEAN')
result = build_rectangular_roof(spec, building_root, building_collection)
```

The root must be a uniquely owned, unparented Blender `EMPTY` already linked to exactly one per-house collection. Its transform is finite, unit scale, `XYZ` rotation with only Z yaw. The method validates finite and bounded numeric fields, 32-bit nonnegative integer seed and `CLEAN`/`AGED` before mutation. It creates one child collection, two closed deck meshes, **one** closed-shingle-field mesh and two ridge planks. Public result fields: `roof_collection`, `deck_objects`, `shingle_object`, `ridge_objects`, `courses_per_side` (count of produced rows on each slope), `shingle_count`. Triangles, bounds and measured gaps remain derived audit data. The five objects are parented to the supplied root and linked only to the roof child collection, with existing `role='roof'` and an additional `roof_part` label. A second roof on the same root and ambiguous root/collection ownership fail before creation. A generation failure removes only that call's child collection, objects, mesh data and private materials; a forced exception after the first deck and a failed Cottage-adapter call were tested without other scene data changing.

The roof calculation is a direct transcription of canonical Phase-9D [`09A/build.py`](../experiments/wooden_roof_system_09a/build.py); from Phase 9F onward **this module is the sole target for roof development**, while 9A remains a frozen historical reproducibility reference, not a second maintained implementation. Same loops, nominal `n_courses`, skip near ridge, counted actual rows, `seed ^ 0x9A08`, 0.185-m spacing, 0.315-m nominal shingle length, per-face material indices, substructure and first caps. The previous `p.width/depth/wall_height/roof_pitch/seed` reads become explicit `RoofSpec` reads; no Cottage import, wall/door code, IRCSS reference or global scene RNG in `roof/`. The tiny internal mesh builder retains `from_pydata`, vertex/face order, `bmesh.ops.recalc_face_normals`, and material append order from the historical Cottage helper. Materials are freshly created per call (four roof slots), unchanged RGB palettes/Roughness 0.92/Metallic 0. `CLEAN`'s fourth roof slot remains allocated but unused by faces; AGED's fourth slot retains the same sparse, seed-dependent moss assignments. No textures. The new output-parenting/collection tags are organizational; mesh-local coordinates and materials are unchanged.

Scope limits: one symmetric rectangle and straight Y ridge; no arbitrary scale/mirroring, non-XYZ root rotation or exporter integration. The strict root precondition is deliberately smaller than a generalized building framework. No root transformation is baked into local mesh vertices. This code is outside the installable Blender add-on; Phase-6 `exporter.py` still accepts IRCSS Geometry-Nodes houses, **not** these Cottage collections.
