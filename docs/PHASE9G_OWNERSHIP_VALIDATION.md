Saved Blender 5.2.2 fixture: [`three_owned_cottages.blend`](../experiments/wooden_roof_system_09f/three_owned_cottages.blend). Every roof contains two `deck`, one `shingles`, two `ridge` tagged meshes. These are **fixture-specific counts**, not a body-count constant in the API. Every polygon's slot index resolves to a real material; slot polygon/triangle sums equal mesh totals. The CLEAN fourth roof material remains a valid assigned slot with **zero** polygons; it is not a missing-material failure. A/B/C have pairwise disjoint object, mesh-data and material IDs. Recollecting in order C/A/B gives unchanged triangle counts. Current geometry has no modifiers or object instancers; geometry is already explicit meshes. Any modifier or instance in a future fixture is refused rather than silently lost.

Negative tests use freshly created, isolated temporary scenes and clean their own IDs afterward. Cases: absent root → `ROOT_INVALID`; Mesh instead of Empty root → `ROOT_INVALID`; wrong collection → `ROOT_COLLECTION`; foreign mesh linked in owner collection → `OBJECT_PARENT`; root-parented mesh outside owner collection → `EXTERNAL_CHILD`; roof with wrong parent → `OBJECT_PARENT`; removed ridge → `ROOF_INCOMPLETE`; conflicting double collection link → `OBJECT_COLLECTION`; roof child collection linked under a second owner → `COLLECTION_SHARED`; nonfinite root transform → `ROOT_TRANSFORM`; foreign object referencing owner mesh → `MESH_SHARED`; foreign object using owner material → `MATERIAL_SHARED`; missing material slots → `MATERIAL_INDEX`; Subsurf modifier → `MODIFIER_UNSUPPORTED`; constraint → `EVALUATION_UNSUPPORTED`; object vertex instancing → `INSTANCE_UNSUPPORTED`. Arbitrary renaming of root, roof collection and roof part still succeeds. No test auto-repairs the failing source before invoking the collector.

The pristine scene's SHA-256 snapshot is computed from counts and full mesh vertices/polygons/material indices, material node inputs, collection graph, parent/data IDs, transforms, active scene/object and selection. It is identical immediately after A/B/C collection, after each temporary negative fixture is removed, and at completion; objects, meshes, materials, collections: **(120, 112, 153, 7)** (see generated report for authoritative counts). Snapshot hashes include session-local Blender pointers and are intended for **within-process before/after equality**, not cross-process comparisons. No persistent data is allocated by collection; only Blender's ephemeral triangulation cache is calculated. The saved 9F `.blend` was reopened independently with its unchanged `reopen.py`: all three local mesh fingerprints, shader assignments, ownership and transforms passed. No historical golden hashes were updated.
