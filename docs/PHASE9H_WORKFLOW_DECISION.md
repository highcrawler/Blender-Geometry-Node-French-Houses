# Phase 9H – workflow decision

**RECOMMENDATION: C — a *thin* owner-scoped export preparation adapter using Blender's native GLB exporter; no custom glTF writer.** The underlying delivery route remains **native GLB**. This is not a preference based on theoretical portability: both routes successfully import all triangles, all five roof objects, local pivots after preparation and all used roof colors, but both demonstrably lose **all four procedural Cottage body colors** (white albedo). A minimal, separately approved asset-copy material strategy is therefore needed for a faithfully colored house. It must not silently change the source shaders or historical golden geometry. The 9G collector already supplies the owner set and export-local matrices; don't reimplement its ownership or the native exporter.

GLB has fewer moving parts at Godot consumption time, with deterministic per-house selection and standalone artifact. The `.blend` importer provides **no material advantage** in this measured fixture: Godot 4.7 invokes Blender/glTF internally and the Godot screenshots/audits match GLB byte-for-byte for A/B. It adds a required configured Blender binary; default active-collection setting imports other houses. Changing active collection in the original three-house file changes only the **single** active import target; importing A/B independently requires saved active-state copies or isolated one-house files. Both routes need root normalization for off-origin standalone assets, and both can import a three-house layout without doing so (Godot B `(35,0,-12)`, C yaw ≈0.45 on Y). GLB source A 783 KB, B 392 KB; single A/B `.blend` about 330/232 KB (not a whole-workflow performance benchmark). Reimport of both was verified.

**Not implemented now:** shader reconstruction, texture baking, material conversion, automated export-copy staging, writer, add-on UI or Pilgrimm integration. The current body shader Noise→ColorRamp cannot be transported as its original procedural graph by either tested glTF path. Any future approximation (e.g. explicitly approved constant-color or baked texture on isolated export-only material copies) must be separately specified, visually accepted, and checked against 9G source-material expectations. The four roof materials need no redesign; unused CLEAN slot removal is normal glTF surface behavior.

**Exactly one next small implementation step:** in a separate milestone, prototype and validate *export-copy-only* conversion of **one** procedural Cottage body material to an approved glTF-compatible color representation, using A's clay as the first test, with original-vs-Godot material evidence. Only after that gate consider the remaining three body shaders and per-owner automation. Never write a glTF encoder.
