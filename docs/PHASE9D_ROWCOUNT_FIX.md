# Phase 9D — row-count root cause and minimal fix

Canonical code: [`experiments/wooden_roof_system_09a/build.py`](../experiments/wooden_roof_system_09a/build.py), function `roof_geometry`. The former `n_courses=ceil(slope_length/0.185)` determines the **upper bound** for both side loops, but `if start > slope_length-.06: continue` can omit the final row. It previously returned `courses=n_courses`, even when that row was skipped. T03 reported 22 but produced 21; T05 reported 19 but produced 18. The skipped rows are not geometrically required: their preceding rows reach beneath the ridge cap.

**Only change to canonical roof function:** retain `n_courses` as the original loop limit and retain the `row>n_courses-4` AGED moisture/material condition **exactly**. Within each side's existing row loop, record the shingle counter before a non-skipped row; after that row, increment `side_courses` only when at least one shingle was actually created. Append this side's count after its loop, assert the two sides agree, and return `courses=courses_by_side[0]` instead of the nominal `n_courses`. No RNG call, material branch, vertex/face creation, row spacing, dimensions or generation order was changed. This avoids a second independent count calculation and makes returned metadata reflect produced geometry.

The 9A source before this fix is independently read from Git commit `de11f7e` by the regression script; its SHA-256 is checked against the value recorded by Phase 9C. Its roof function and the corrected one are both run in Blender for all 16 states. The former 9B strict audit assumed `ceil` rows; the 9D test extracts the historical geometry audit without changing its thresholds and derives its **audit-only** row range from the vertices it inspects. No archival 9B/9C audit or output is rewritten. Direct 9A top-level build was also re-run successfully in a temporary directory: both Long variants yielded 20 courses, 1,137 shingles, 13,692 roof triangles and all 12 renders without writing to archived files.
